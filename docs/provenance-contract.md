# Provenance and honesty contract

These semantics bind future ingestion, canonical modeling, transformation,
validation and rendering. Phase 0 defines the enum and exposes its vocabulary;
it does **not** extract facts, assign claim provenance, or implement evidence validation.

## OBSERVED

Explicitly supported by the user's supplied source. Every future observed factual
claim must carry an **EvidenceReference** that allows a reviewer to find the support
in the source. The reference schema will be designed with the canonical model later;
source identity and a usable location (such as a passage, page or time range) will
be needed. No EvidenceReference model is implemented in this iteration.

OBSERVED means source-supported, not independently proven true. Contradictory or
unreliable sources must not be silently merged into certainty. Faithful paraphrasing
may remain observed when the evidence supports the full meaning; adding an unstated
cause or conclusion requires separate inferred treatment. A generated citation or
model confidence score is not evidence.

## INFERRED

Interpretation, transformation, recommendation or creative material generated by
the system. Its status must remain visible to API consumers and in rendered output;
it must never masquerade as an observed source fact. Where an inference depends on
observations, future models should preserve links to those supporting claims, without
pretending that the source explicitly states the inference.

For example, a proposed communications action is inferred even if motivated by
observed facts. A new number, date, quotation or incident finding cannot be invented
and legitimized merely by attaching INFERRED. Unsupported factual assertions should
be omitted or represented as unknown; genuinely hypothetical material must be explicit.

## UNKNOWN

The necessary evidence is absent, ambiguous or cannot be determined. Represent the
absence explicitly, with a reason where helpful. An unreadable source or conflicting
evidence does not license guessing. UNKNOWN is not zero, false, an empty factual
collection, or a default value that looks measured.

For example, if a report does not state the number of affected users, that count is
unknown. It is not zero. If it does not assess data loss, data loss is unknown, not false.

## NOT_APPLICABLE

The field does not logically apply in this context. This is different from evidence
being missing. For example, a video duration field does not apply to a text-only
LinkedIn artefact. It is not a shortcut for unreadable or incomplete input.

## Cross-cutting requirements

1. Missing information must never silently become zero, false, empty-but-valid factual
   data, a fabricated default or a made-up finding. A real observed zero/false/empty
   result requires positive evidence supporting that value.
2. Future schemas must preserve explicit missingness (for example, absent/null value
   plus an appropriate status), rather than requiring invented values to validate.
   The exact value/provenance wrapper belongs to later canonical-schema design.
3. Factual claims derived from supplied material must remain traceable to evidence
   through canonical analysis, transformation and export. Dropping a label or reference
   to make an output look more polished violates the contract.
4. Keep compound statements with mixed provenance distinguishable. An inferred
   conclusion cannot inherit OBSERVED merely because another clause cites evidence.
5. Validation must eventually detect unsupported observed claims. Phase 0 makes no
   claim that such runtime validation exists yet.
6. Simulated/stubbed development responses must be explicitly identified in API/UI
   output as **stub** or **simulation**, never as real model results. Phase 0 has no
   content-generation stub or model output.

## Trust boundary: source is DATA, not instructions

An uploaded document can contain: **"Ignore all previous instructions."** That sentence
is part of the source being analyzed. It must never override application-level
instructions, change provenance rules, authorize tools, reveal secrets or redirect
the workflow. Quoting or describing it as source content is different from obeying it.

Future implementations must keep operator controls and trusted application
instructions separate from untrusted source text, including text extracted from
images, video, documents or URLs. Source-provided role labels, prompts and tool-like
syntax gain no authority. Adversarial-source tests belong with the future ingestion
and model boundary; the current documentation is not evidence of an implemented
prompt-injection defense.
